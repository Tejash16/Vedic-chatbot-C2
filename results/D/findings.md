# Session D findings: question-and-answer sets (Stage D, laptop1)

1. **Sub-corpus.** 1,499 chunks from 165 verses of the 10k corpus (verses holding a test question, seed-7 order, at most 10 chunks per verse with the gold chunk always in), so commentaries on the same mantra compete as in the full corpus. It holds 165 test questions (en 46, hi_roman 44, sa_quote 40, hi 35) and 123k words; IDs in `results/D/subcorpus_chunk_ids.txt`.
2. **Method.** `claude-haiku-5-5`, Batch API, effort low, JSON schema, one request per passage: first every distinct point as an exact quote, then one Hindi and one English question per point. 1,499 requests plus 24 retries (1.6 %, fewer sets than points) gave 9,703 points and 9,693 sets for $0.63 ($0.42 per 1,000 passages). Session D spent $1.27 of $10 in all (`spend.log`).
3. **Sets per passage** (short < 52 words / medium 52-96 / long >= 97): generated 4.0 / 7.1 / 8.2; kept after all filters 2.9 / 4.4 / 6.2; kept without filter 3: 3.8 / 6.8 / 8.0.
4. **Sets per 100 words:** 7.9 generated, **5.4 after all filters**, 7.5 without filter 3 (by bin 8.7 / 6.0 / 4.4 after all filters; by language hi 4.8, en 6.2, sa 7.8).
5. **Share removed by each filter** (of generated sets, applied in order): answer not found word for word 1.4 %; name or Sanskrit term absent from passage and verse details 2.6 % (calibrated on the 360 test questions, where it flags 1); own passage not in the top 10 with bge-m3 dense 26.7 %; merging repeats 0.0 % (2 near-identical pairs in 35k). Filter 3 misses 38 % of Hindi and 48 % of English questions; I apply it per question (a missing question is left out of the index, a set goes only if both miss); the strict "both must hit" rule would remove 58 %.
6. **Coverage:** 75 % of a passage's sentences are overlapped by at least one kept set (81 / 72 / 73 % by bin); 89 % without filter 3, 91 % for every verbatim answer.
7. **Scale-up** (`../local/final/sets-estimate.md`): 106 works, 20.5M words, ~260,600 requests (chunk-count formula within 1 % of the real 10k corpus). Estimated **1.07M sets after all filters, 1.51M without filter 3**, for **about $112** on the Haiku Batch API (hi $54, en $19, sa $13, other languages $26). Each request carries ~1,240 fixed input tokens, so several passages per request would cut the cost.
8. **Search test** (bge-m3 dense, 1,499-passage index, each passage scored by the max over its own vector and its question vectors, shared scorer). Chunk R@10 / verse R@10 / MRR@10: passages only .467 / .679 / .280; plus all kept sets in both languages .503 / .764 / .323; **plus all sets without filter 3 .612 / .794 / .373**; plus strict filter 3 .418 / .715 / .264; sets only, no passage vectors .491 / .758 / .321.
9. **Best K per passage:** best 5 gives .479 / .758; best 10, 20 and 40 equal all kept sets, because passages keep 4.5 sets on average after filter 3.
10. **Source language only vs both languages:** source-language questions alone give .461 / .721, no better than passages alone; both languages give .503 / .764. The gain comes from cross-language questions (chunk R@10 .373 to .441 with filter 3, .627 without it), while same-language questions stay level (.619 to .603 / .587).
11. **By group** (chunk R@10, passages only to all sets without filter 3): en .70 to .89, hi .63 to .77, sa_quote .55 to .75, hi_roman .02 to .07. Romanized Hindi is nearly invisible to bge-m3 dense, and sets do not fix it.
12. **Leakage check:** the test questions and the sets both come from Haiku, but only 1.2 % of test questions have a set question on their gold chunk at cosine >= 0.90 (6 % at >= 0.85, median best 0.67). Removing those near copies per question still leaves R@10 at .600 without filter 3.
13. **Verdict: indexing sets improves recall.** Index both languages and every set that passes filters 1 and 2 (+14.5 points chunk R@10 and +11.5 verse R@10 over passages alone). Drop filter 3, or keep it only as a quality flag: it removes exactly the questions that open a new route to their passage. Latency rises 2 ms at p50 (1.5k to 20k vectors).
14. **Sonnet vs Haiku on the same 100 passages:** `claude-sonnet-5-5` writes fewer points (4.8 vs 6.4 per passage), fewer non-verbatim quotes (0.2 % vs 1.6 %), loses more to filter 3 (36 % vs 28 %), keeps fewer sets (2.9 vs 4.4) and covers fewer sentences (67 % vs 77 %), at 13 times the price ($5.44 vs $0.42 per 1,000 passages). A scholar has not reviewed them yet: 60 sets per model, blinded, are in `../local/final/sets-for-review.csv`, with the key in `sets-for-review-answer-key.csv`.
15. **Caveats:** the test questions are synthetic only (no real group yet), and filter 3 and the search test use the same embedder. Re-run the search test when real questions arrive.
